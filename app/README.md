# Приложение Крот (Windows, macOS, Linux)

Окно пульта: состояние узлов и клиенты. Логика та же, что у CLI `krot`: оба используют пакеты `internal/`. Приложение только показывает данные и спрашивает пользователя.

## Что умеет сейчас

- **Мастер «Новая установка»** с нуля:
  1. Схема: каскад (вход в России + выход за границей) или один сервер.
  2. Серверы: доступен ли вход (или единственный сервер) из России без VPN (P-57), проверка по паролю root, перевод на ключ. Выход, не видный из России, подключается через вход.
  3. Домен: поддомены можно переназвать, мастер показывает, какие A-записи создать, и проверяет их у трёх резолверов. Без домена — урезанный набор.
  4. Состав: каталог модулей с пояснениями и живым предпросмотром плана.
  5. Установка по плану с прогрессом. После сбоя продолжает с упавшего шага.
  6. Где ключ пульта.

  Дальше — только после зелёной проверки. Пароль root не сохраняется.
- **Файл узлов.** Открыть `inventory.yaml`. Путь запоминается в `~/.krot/app.json`.
- **Узлы.** Цвет состояния и сводка: система, модули, итог проверок `vpnkit-watch` (без оповещений).
- **Модули узла.** Что стоит, чего не хватает, установка или переустановка. Подтверждение — вторым нажатием, ход виден в окне. Движок тот же, что у `krot install`.
- **Клиенты входа.** AmneziaWG, подписка, Telegram-прокси: добавить, карточка (QR, ссылки, копирование, папка), удалить.
- **Обновления.** Если на узлах стоят модули старее, чем в этой версии приложения (скрипты или закреплённые версии программ), вверху появляется полоса «Доступны обновления». Обновление идёт по шагам в порядке установки, с откатом; службы перезапускаются, только если их настройки или программа изменились.
- **Резервные копии.**
  - Забрать свежую с проверкой: sha256, расшифровка ключом пульта, ключевые файлы модулей.
  - Список копий на компьютере.
  - «Восстановить клиентов»: подписка и Telegram возвращаются из копии, AWG — из хранилища, без перевыдачи.
- **Оповещения в Telegram.**
  - Проверка бота, поиск своего chat id, тестовое сообщение, применение на узлах.
  - Запросы к Telegram идут с выхода: из России API часто закрыт.
- **DNS через Cloudflare в мастере.** Создаются только недостающие записи, существующие не трогаются.
- **Обновление себя.** При запуске и раз в 6 часов — проверка последнего релиза; «Обновить» скачивает сборку под эту систему, сверяет с `SHA256SUMS`, подменяет себя (на macOS — весь `.app`) и перезапускается. Версию и адрес релизов задаёт сборка (`-ldflags "-X main.version=… -X main.updateRepo=…"`), у сборок для разработки обновлений нет.
- **Пароли** хранилища и ключа спрашиваются окном и живут только в памяти.
- **Данные с узлов** попадают в страницу только как текст.

## Сборка

Нужны Go и Node.js (npm). Wails CLI ставится так:

```
go install github.com/wailsapp/wails/v2/cmd/wails@v2.16.0
```

Затем:

```
cd app
wails build          # → build/bin/krot-app(.exe)
wails dev            # живая перезагрузка при правке
```

- Wails v2.16 стабильный; v3 пока beta.
- Отдельного `go.mod` у приложения нет: оно часть Go-модуля `krot`.
- macOS собирается на macOS (`wails build -platform darwin/universal`).
- Linux: окно на GTK3 + WebKitGTK 4.1 (Arch/CachyOS: `gtk3 webkit2gtk-4.1`; Debian/Ubuntu: `libgtk-3-dev libwebkit2gtk-4.1-dev`). На свежих дистрибутивах есть только WebKitGTK 4.1, поэтому тег обязателен: `wails build -tags webkit2_41`. Нужны Node.js и npm (Arch/CachyOS: `pacman -S nodejs npm`): `frontend/dist` в git не лежит, его собирает `wails build`.
- Снимок окна без вывода на экран (Linux): `xvfb-run` с `GDK_BACKEND=x11` и `KROT_APP_OPEN`, снимок — `import -window root`.

## Для проверки интерфейса

Интерфейс проверяется без мыши через `KROT_APP_OPEN`:
- `<узел>/<awg|sub|tg>/<имя>` — открыть карточку клиента;
- `install:<узел>/<модуль>` — переустановить модуль;
- `alerts` — окно оповещений;
- `update` — сразу обновиться до последнего релиза (если сборка знает версию и адрес релизов);
- `wizard` — открыть мастер (шаг выбора схемы);
- `wizard-entry:<IP>` — шаг входа с проверкой адреса;
- `wizard-catalog:<cascade|solo>` — шаг состава (каталог с предпросмотром плана, домен example.org);
- `wizard-domain:<домен>:<IP входа>:<IP выхода>:<поддомен входа>:<поддомен выхода>` — шаг домена с проверкой DNS.

## Чего пока нет

- **Схема «один сервер» на чистом сервере ещё не проходилась** — план и агенты готовы.
- **Мастер целиком на чистых серверах ещё не проходился.** По отдельности на тестовых серверах проверены:
  - доступность и DNS;
  - перевод на ключ (`krot bootstrap`);
  - план и установка (`krot deploy`), обновление всех модулей;
  - отказ входу, недоступному из России.
- В мастере: первые клиенты (сейчас их добавляют на экране входа после установки).
- Восстановление узла целиком на новый сервер.
