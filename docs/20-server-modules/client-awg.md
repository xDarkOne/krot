# client-awg — вход AmneziaWG для приложений

**Роли:** entry, solo.
**Зависит от:** base-host, amneziawg; в каскаде ещё split-routing и cascade-awg0.
**Код:** [agent/client-awg/](../../agent/client-awg/), клиенты — `vpnkit clients add|show|list|del` ([internal/clients/](../../internal/clients/)).

Клиенты подключаются приложением AmneziaVPN (5.0.2+) или любым клиентом AmneziaWG 3.1: профиль по QR-коду или ссылке `vpn://`. Домен не нужен.

## Как устроено

| | Умолчание | Параметр inventory |
|---|---|---|
| Интерфейс | `awg2` (AmneziaWG 3.1) | `iface` |
| Сеть клиентов | `10.9.2.0/24`, шлюз и DNS — `10.9.2.1` | `net` |
| Порт | случайный UDP 20000–60000, хранится в хранилище | `port` |
| MTU / MSS | 1260 / 1220 (место под padding 3.1, [P-06](../60-pitfalls.md)) | `mtu`, `mss` |
| ip rule (каскад) | 208 — российское напрямую, 212 — остальное в каскад | `rule_main`, `rule_cascade` |

**Секреты входа генерирует пульт:** ключ сервера, HeaderProtectionKey, порт и свою обфускацию (Jc/Jmin/Jmax, S1–S4, диапазоны H, I1/I2 — имитация DTLS/RTCP), отличную от обфускации туннеля между серверами. Хранятся в `<узел>/client-awg/<iface>/*`. `RandomTrailers` выключен, см. [P-13](../60-pitfalls.md).

**Каскад** (`entry`): в `PostUp` входа

```
ip rule add from 10.9.2.0/24 fwmark 0x1 table main priority 208   # российское — напрямую
ip rule add from 10.9.2.0/24 table 200 priority 212               # остальное — в каскад
ip route replace 10.9.2.0/24 dev awg2 table 200
```

а в `inet vpnkit_split` трафик с входа к российским сетям и доменам получает метку 0x1. DNS клиентам отдаёт dnsmasq из split-routing.

**Один сервер** (`solo`, `VK_CASCADE=0`): правил разделения нет, клиенты выходят прямо в интернет. Split-routing тоже нет, поэтому вход ставит свой простой dnsmasq (`10-vpnkit-dns.conf`: слушает только петлю и шлюзы входов, наружу — 1.1.1.1 и 8.8.8.8). Российские сайты, закрытые для заграницы, в этой схеме не открываются: это ограничение схемы, а не входа.

**Фаервол** (`/etc/nftables.d/30-vpnkit-client-<iface>.nft`):
- input: UDP-порт входа, всё с интерфейса входа (клиентам нужен DNS);
- forward: accept с интерфейса входа; ограничение MSS в обе стороны;
- NAT: masquerade сети клиентов на выходе из любого интерфейса, кроме самого входа.

## Клиенты

**Реестр клиентов — сам конфиг сервера:** перед каждым `[Peer]` стоит комментарий `# name: <имя>`. Повторная установка модуля переписывает только `[Interface]`, пиры переносятся как есть; вход перезапускается, только если `[Interface]` изменился.

**Добавление** (`vpnkit clients add <узел> <имя>` или кнопка в окне):
1. Пульт генерирует ключи и PSK.
2. Пир дописывается в конфиг (с копией) и в живой интерфейс через `awg set`. Вход не перезапускается.
3. Профиль сохраняется в хранилище (`<узел>/clients/<имя>/<iface>`), на компьютере появляются `~/.vpnkit/clients/<узел>/<имя>.{conf,vpn.txt,qr.png}` (права 600).

Ссылка `vpn://` — формат AmneziaVPN: контейнер `amnezia-awg2`, `protocol_version 3.1`.

**Удаление** (`vpnkit clients del <узел> <имя>`):
1. Конфиг копируется в `/var/lib/vpnkit/clients-backup/`.
2. Блок `# name: <имя>` удаляется из файла.
3. Пир снимается с живого интерфейса через `awg set … peer … remove` без перезапуска: у остальных клиентов соединение не рвётся.
4. Проверяется, что пира в интерфейсе больше нет; профиль удаляется из хранилища и с компьютера.

Если сервер заменён и конфиг потерян, `vpnkit clients resync <узел>` возвращает пиры из хранилища.

## Совместимость
- AmneziaVPN ≥ 5.0.2 или клиенты AmneziaWG 3.1.
- Роутеры OpenWrt с kmod AmneziaWG 3.1 принимают тот же профиль.
- Профиль содержит IP сервера: при смене адреса клиентам нужен новый профиль (ключи те же).

## Обновление
Смена обфускации требует перевыдать профили всем клиентам входа. Поэтому:
1. Рядом поднимается **новый вход** (`iface`, `net`, `port` другие).
2. Клиентов переводят по одному.
3. Старый вход гасят, когда на нём никого не осталось.

## Проверка
```
awg show awg2 dump | awk 'NR>1 && $5>0' | wc -l     # пиры с рукопожатием
ip rule | grep -E '^(208|212):'                     # каскад
dig +short @10.9.2.1 ya.ru                           # DNS для клиентов
```

На тестовых серверах:
- клиент, подключённый через вход и каскад, видит зарубежные сайты с адреса выхода, а Яндекс — с адреса входа (разделение работает);
- после добавления и удаления клиента конфиг побайтно совпал с исходным, вход не перезапускался.
