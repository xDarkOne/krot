# monitoring — проверки узлов и оповещения в Telegram

**Роли:** entry, exit, solo. **Зависит от:** base-host. **Код:** [agent/monitoring/](../../agent/monitoring/)

Модуль следит за состоянием узла каждые 5 минут и сообщает о проблемах в Telegram (или в журнал, если бот не настроен). Это позволяет узнать о поломке раньше, чем клиенты начнут жаловаться, что VPN не работает.

## Как устроено

- `/usr/local/sbin/vpnkit-watch.sh` — скрипт проверок. Только читает состояние узла, ничего не меняет.
- `/etc/vpnkit/watch.conf` — настройки: имя узла, адрес выхода, данные соседа, дополнительные службы.
- `/etc/vpnkit/alert.env` — токен Telegram и получатели (создаётся только если в пульте есть секреты `_global/alert/tg_token` и `_global/alert/tg_chats`).
- `/var/lib/vpnkit/watch.state` — состояние проверок: сколько раз подряд не прошла каждая проверка и отправлялось ли уже оповещение.
- `vpnkit-watch.service` — oneshot-юнит, запускает скрипт один раз.
- `vpnkit-watch.timer` — запускает проверку каждые 5 минут (первый раз через 3 минуты после загрузки).
- Пакеты: `curl`, `bind9-dnsutils`, `openssl`, `iputils-ping`.

Порты и правила nftables модуль не создаёт.

### Проверки

Скрипт сам определяет, что проверять на узле:

- **Службы:** включённые юниты стека VPN (`awg-quick@*`, `wg-quick@*`, `nftables`, `dnsmasq`, `fail2ban`, `xray`, `sing-box`, `nginx`, `docker`, `danted`, `mtproxyl`, `telemt`, `mss443`) плюс `SERVICES_EXTRA`. Экземпляры шаблонов ищутся по ссылкам `*.wants/`, потому что `systemctl list-unit-files` их не показывает.
- **Каскад:** если есть интерфейс `awg0` и известен `EXIT_IP`, проверяется, что выход через `awg0` даёт именно этот адрес.
- **Сосед:** если задан `PEER_TUN`, отправляется 5 пингов по туннелю. Недоступен считается только если не дошёл ни один.
- **Сосед снаружи:** если заданы `PEER_TCP` и `PEER_PUBLIC`, проверяется, что TCP-порты соседа отвечают снаружи.
- **DNS:** если работает `dnsmasq`, проверяется ответ на `dig @127.0.0.1 ya.ru`.
- **MTProto:** если есть `/etc/vpnkit/mtproxy.env`, проверяется, что `telemt` слушает локальный порт и nginx stream ведёт TCP/443 в него. Если есть Docker-контейнер `mtproxyl`, проверяется, что он запущен.
- **Split:** если есть nftables-набор `inet vpnkit_split ru_nets` или `inet split ru_nets`, проверяется, что в нём больше 5000 записей.
- **Диск:** заполненность `/` меньше 85%.
- **Сертификаты:** Let's Encrypt в `/etc/letsencrypt/live/*/cert.pem` не истекают раньше чем через 14 дней.
- **Резервные копии:** если включён `vpnkit-backup.timer`, свежая копия в `/var/backups/vpnkit/*.tar.gz.age` не старше 30 часов.
- **Ядро AmneziaWG:** если модуль `amneziawg` загружен, проверяется, что он есть в последнем ядре из `/boot/vmlinuz-*`.
- **dpkg:** нет недоустановленных пакетов.

### Оповещения

- 🔴 — если проверка не проходит **2 раза подряд** (10 минут).
- 🟢 — когда проверка снова проходит.
- Если сообщение не доставлено, повторная попытка будет на следующем прогоне.
- Если `TG_TOKEN` и `TG_CHATS` не заданы, сообщения пишутся в журнал: `logger -t vpnkit-watch`.
- При неудаче отправки Telegram-сообщение повторяется напрямую через внешний интерфейс.

### Каскад и solo

- **entry** проверяет exit по туннелю и снаружи (порты из `peer_tcp`).
- **exit** проверяет entry по туннелю и снаружи.
- **solo** проверяет только самого себя: службы, диск, сертификаты, копии, ядро, dpkg.

## Параметры

Переменные `VK_*` готовит пульт. Те, что имеет смысл менять, задаются в inventory как `modules.<модуль>.<имя>` (имя — в нижнем регистре, без `VK_`).

| Переменная | Умолчание | Что значит |
|---|---|---|
| `peer_tcp` | пусто | TCP-порты соседа, которые проверяются снаружи. |
| `services_extra` | пусто | Дополнительные службы, которые обязаны быть активны. |

Дополнительные переменные из пульта:

| Переменная | Значение |
|---|---|
| `VK_NODE` | Имя узла. |
| `VK_EXIT_IP` | Публичный IP выхода (для проверки каскада). |
| `VK_PEER_NAME` | Имя соседа. |
| `VK_PEER_TUN` | Адрес соседа в туннеле. |
| `VK_PEER_PUBLIC` | Публичный IP соседа. |
| `VK_PEER_TCP` | Список портов соседа для внешней проверки. |
| `VK_SERVICES_EXTRA` | Дополнительные службы. |
| `VK_TG_TOKEN` | Токен Telegram-бота (из секретов пульта). |
| `VK_TG_CHATS` | Получатели оповещений через пробел (из секретов пульта). |

## Проверка

`verify` запускает скрипт один раз с временным файлом состояния `/run/vpnkit-watch.verify`, проверяет, что скрипт дошёл до конца и таймер включён. Провалы самих проверок **не считаются** провалом модуля — о них сообщат оповещения.

Полезные команды:

```bash
# Прогонить проверки вручную
/usr/local/sbin/vpnkit-watch.sh

# Посмотреть результат последнего прогона
journalctl -t vpnkit-watch -n 50

# Проверить, что таймер включён
systemctl is-enabled vpnkit-watch.timer

# Посмотреть состояние проверок
cat /var/lib/vpnkit/watch.state
```

## Ловушки

- [P-62](../60-pitfalls.md) — в новом ядре нет модуля AmneziaWG, после перезагрузки туннели не поднимутся.

## Откат

`rollback` отключает `vpnkit-watch.timer` (если он был создан этим прогоном), восстанавливает снапшот и выполняет `systemctl daemon-reload`.
