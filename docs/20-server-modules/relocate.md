# relocate — переезд узла на новый адрес

**Роли:** entry, exit, solo. **Зависит от:** base-host.
**Код:** [agent/relocate/](../../agent/relocate/)

Сервер можно склонировать у хостера на другой адрес. Все настройки Крота (туннель каскада, мониторинг, исключения защиты, MTProto) прошиты адресами, поэтому после клонирования нужно их переписать. Модуль ставит команды, которые делают это за вас. Пока их не запустить, ничего не работает в фоне.

## Как пользоваться

1. Клонируйте сервер у хостера, включите клон.
2. Зайдите на клон по SSH и выполните `relocate-ИМЯ` (имя узла из inventory) или просто `relocate`.
3. Команда покажет найденные старые адреса, предложит новые (по умолчанию — те, что сейчас на сетевом интерфейсе), перечислит файлы к правке и после подтверждения применит замену, перезапустит службы и проверит туннель.
4. Каскад: сосед получает те же замены — автоматически, если с этого узла есть вход по ключу на соседа, иначе команду для него `relocate` напечатает.
5. Поменяйте записи домена на новый адрес. Если адрес на интерфейсе ещё не совпадает с настройками — перезагрузите сервер.

`vpnkit-reip --map СТАРЫЙ НОВЫЙ [--map …] [--apply]` — то же без вопросов: без `--apply` только показывает, что изменится. Копии прежних файлов лежат в `/root/reip-bak-<время>`.

## Что правится

`/etc/network/interfaces`, `/etc/hosts`, `/etc/vpnkit/*.conf`, `/etc/traffic-guard.exempt`, конфиги AmneziaWG и WireGuard, sing-box, telemt, `/etc/nftables.d/*.nft`, плюс пути из `/etc/vpnkit/reip.extra` (по одному в строке). Маска сети не меняется; если у клона другая, поправьте `/etc/network/interfaces` вручную. Сеть не перезапускается, чтобы не оборвать SSH.

## Ограничения

- Сценарий рассчитан на `ifupdown` (Debian/Ubuntu со статическим адресом в `/etc/network/interfaces`).
- Сертификаты привязаны к доменам, а не к адресам, и после смены записей продолжают работать.
