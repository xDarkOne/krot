# subscriptions — персональные подписки VPN-входов

**Роли:** entry, solo. **Зависит от:** xray, nginx-tls. **Код:** [agent/subscriptions/](../../agent/subscriptions/)

Модуль раздаёт клиентам одну персональную ссылку на все входы. Клиент получает `https://<имя>/u/<токен>`, открывает её в Happ, v2rayNG или Hiddify и получает актуальные входы; новые входы приходят в подписку без замены ссылки.

## Единая подписка INCY

В разделе **«Клиенты»** выберите **«Подписка + профиль AmneziaVPN»** и нажмите **«Создать»**. Этот вариант выбран по умолчанию, если на узле доступны AmneziaWG и актуальный модуль `subscriptions`. Крот создаёт оба подключения под одним именем, сразу добавляет AmneziaWG в подписку и открывает карточку с единой ссылкой, QR и отдельным файлом для AmneziaVPN. Используйте отдельное имя и профиль для каждого устройства.

```sh
krot clients add <узел> <имя> --combined
```

Для уже созданных подписки и профиля с одинаковым именем нажмите **«Добавить AmneziaWG в подписку»** в карточке подписки или выполните:

```sh
krot clients amnezia-publish <узел> <имя> --sub
```

Добавьте основную ссылку или QR из карточки в INCY. В одной подписке будут VLESS XHTTP, VLESS PQ, Hysteria2 (если установлен) и одноимённый AmneziaWG. Если была добавлена ссылка из кнопки **«Копировать подписку без AWG»**, замените её основной ссылкой из **«Копировать ссылку»**, чтобы получить и профиль AWG. Формат тела — Base64 со ссылками по одной на строку, профиль AmneziaWG передаётся как `amneziawg://<base64url-conf>`. Профили, уже опубликованные в Кроте, подключаются к единой подписке при обновлении модуля `subscriptions`. [Формат подписки INCY](https://docs.incy.cc/subscription-format/)

В INCY Desktop 3.9.0 на Linux профиль AmneziaWG может показывать `n/a` во встроенном тесте задержки. Этот тест запускает проверку через Xray, а само подключение AWG использует отдельный движок. Для диагностики подключитесь по AWG, проверьте HTTPS и рукопожатие соответствующего пира на сервере. Для других платформ и сборок проверяйте поддержку отдельно.

Если после подключения страницы не открываются и скорость отправки через TUN резко растёт, проверьте `ip -4 route get <IPv4-адрес сервера AWG>`. В INCY Desktop 3.9.0 на Linux обнаружена петля: при полном туннеле сам адрес сервера AWG может маршрутизироваться в `tun_incy`. Тогда показанная скорость отражает пакеты, циркулирующие внутри устройства. Адрес сервера должен быть доступен через физическое подключение. Как временный обходной путь в NetworkManager можно добавить маршрут `/32` до сервера через шлюз этого подключения перед запуском AWG:

```sh
nmcli device modify <интерфейс> +ipv4.routes '<IPv4-адрес-сервера>/32 <локальный-шлюз>'
```

Изменение действует на текущее подключение. Актуальные интерфейс и шлюз можно посмотреть в `ip -4 route get <IPv4-адрес-сервера>` при отключённом VPN.

Ссылка совместимости всегда отдаёт подписку без AWG. У единой подписки отдельный секретный URL, который даёт доступ к закрытому ключу клиента. Nginx выбирает файл по URL, поэтому `User-Agent` не влияет на состав подписки. Передавайте ссылку только владельцу устройства. Для клиентов без поддержки AmneziaWG доступна ссылка совместимости, а для приложения AmneziaVPN — файл `.vpnuri` со строкой `vpn://`.

Опубликованный профиль хранится в закрытом реестре `/etc/vpnkit/users.json` и попадает в его резервные копии. Кнопка **«Убрать AmneziaWG из подписки»** и команда `krot clients amnezia-unpublish <узел> <имя> --sub` отзывают единую ссылку и отдельный файл. Ссылка подписки без AWG продолжает работать. Чтобы отключить уже импортированный профиль, удалите одноимённого клиента AmneziaWG.

## Как устроено

Модуль не открывает свои порты, не создаёт nftables-правил и не ставит systemd-юниты. Он использует существующую витрину nginx-tls и добавляет в неё раздачу файлов подписок.

Установка:

- требует `/etc/vpnkit/xray.env` — без xray подписке нечего раздавать;
- требует витрину `/etc/nginx/sites-available/vpnkit-<sub_name>` — сначала должен быть установлен nginx-tls;
- копирует генератор подписок из `$VK_RUN/src/vpnkit-gen.py` в `/usr/local/sbin/vpnkit-gen.py` с правами `755`;
- создаёт каталог подписок `/var/www/vpnkit-sub/u/`;
- пишет настройки генератора в `/etc/vpnkit/sub.env` с правами `600`:
  - `SUB_NAME=<sub_name>`
  - `OUTDIR=/var/www/vpnkit-sub/u`
  - `ROUTING=<routing>`
  - `ROUTING_NAME=<routing_name>`
- делает снапшот `/etc/nginx/vpnkit.d/<sub_name>-site-routing.conf`, если он уже есть;
- пишет `/etc/nginx/vpnkit.d/<sub_name>-site-sub.conf` с правами `644`:

```nginx
location ^~ /u/ {
    access_log off;
    if ($uri !~ "^/u/[0-9a-f]{32}([.]vpnuri)?$") { return 404; }
    alias /var/www/vpnkit-sub/u/;
    types { application/octet-stream vpnuri; }
    default_type text/plain;
    add_header Cache-Control "no-store" always;
    try_files $uri =404;
}
```

- проверяет и перезапускает nginx: `nginx -t -q`, `systemctl reload nginx`;
- запускает генератор: `/usr/local/sbin/vpnkit-gen.py build`.

Ссылка клиента имеет вид:

```text
https://<sub_name>/u/<токен>
```

Чужой токен отвечает обычным `404` витрины.

В каскаде модуль занимает роль `entry`: он раздаёт подписки на входы, созданные другими модулями. На одном сервере он работает как `solo` и раздаёт доступные входы этого сервера.

## Параметры

Переменные `VK_*` готовит пульт. Те, что имеет смысл менять, задаются в inventory как `modules.<модуль>.<имя>` (имя — в нижнем регистре, без `VK_`).

| параметр inventory | умолчание | что значит |
|---|---|---|
| `sub_name` | `имя туннелей` | имя витрины nginx-tls, под которым раздаются подписки: `https://<sub_name>/u/<токен>` |
| `routing` | `1` | включать правила «российское — напрямую» для Happ и INCY на путях `/h` и `/i` |
| `routing_name` | `VPN` | имя набора правил, как он подписан в приложении |

## Проверка

`verify.sh` проверяет через `443` порт:

- берёт токены из `/etc/vpnkit/users.json`;
- для каждого токена запрашивает `https://<sub_name>/u/<токен>`;
- декодирует ответ `base64 -d`;
- требует минимум две ссылки с `://`;
- проверяет, что опубликованные файлы `.vpnuri` содержат ссылку `vpn://`;
- проверяет, что случайный чужой токен отвечает `404`;
- если `routing=1`, проверяет, что `/h` отвечает редиректом на `happ://routing/onadd/…`, а `/i` — на `incy://routing/onadd/…`.

Полезные команды:

```bash
test -d /var/www/vpnkit-sub/u && echo ok
ls /var/www/vpnkit-sub/u | wc -l
curl -s --resolve example.org:443:127.0.0.1 https://example.org/u/<токен> | base64 -d | grep -c '://'
```

## Ловушки

- [P-50](../60-pitfalls.md): полные ссылки с токенами не должны попадать в журнал; для `location /u/` включено `access_log off`.

## Откат

`rollback.sh` восстанавливает снапшот nginx-конфигурации, затем, если конфигурация nginx корректна, перезагружает nginx. Каталог `/var/www/vpnkit-sub/u/` с подписками остаётся на сервере, но после отката подписки больше не раздаются.
