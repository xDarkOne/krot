# traffic-guard — защита от сканеров и госсетей

**Роли:** entry, exit, solo. **Зависит от:** base-host.
**Код:** [agent/traffic-guard/](../../agent/traffic-guard/)

Входящие соединения от известных сканеров и сетей госорганов отбрасываются на самом раннем этапе (nftables, prerouting, приоритет raw). Меньше проб — меньше шансов, что сервер найдут и внесут в блок-листы.

## Как устроено

- `/usr/local/sbin/traffic-guard` — скрипт на Python: `apply` (по умолчанию), `status`, `remove`.
- `/etc/traffic-guard.exempt` — исключения, которые не блокируются никогда. Файл создаёт Крот: адреса всех узлов из inventory, адрес компьютера, с которого идёт установка, и `modules.traffic-guard.exempt`.
- `/var/lib/traffic-guard/` — кэш списков.
- `traffic-guard.service` (oneshot при загрузке) и `traffic-guard.timer` (раз в сутки, около 04:20).
- nft-таблица `inet guard` — своя, чужие правила не затрагиваются. Правило действует только на входящем интерфейсе маршрута по умолчанию.

Списки берутся из публичного репозитория shadow-netlab/traffic-guard-lists (antiscanner, skipa, government_networks). Каждый список проверяется целиком: любая непонятная строка, выход за границы размера или резкое изменение размера — отказ, остаётся прошлая копия из кэша.

## Безопасность

- Частные сети, loopback и CGNAT (100.64.0.0/10, Tailscale) не блокируются.
- Адреса узлов — в исключениях, поэтому каскад между узлами не ломается. При клонировании на новый адрес `vpnkit-reip` переписывает этот файл.
- Если ни один список недоступен и кэша нет, правила не меняются.

## Проверка и откат

Проверка: таблица `inet guard` на месте, набор не пуст, таймер включён, узлы в исключениях. Откат прогона удаляет таблицу и службы, если их поставил этот прогон.
