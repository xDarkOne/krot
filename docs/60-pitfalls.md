# Ловушки

Каждая из них уже стоила времени или простоя. Формат пункта: **где бьёт → как проявляется → как защищается инструмент.**
Модули ссылаются на номера вида `P-NN`.

## Сеть и фаервол серверов

**P-01. `flush ruleset` в `/etc/nftables.conf`** (оба сервера). Ловушка остаётся для новых узлов с дефолтным `nftables.conf`, и ещё одна её половина — `ExecStop=nft flush ruleset` в штатном юните.
- `systemctl restart nftables` или `nft -f /etc/nftables.conf` стирает чужие таблицы: Docker (`ip nat`/`ip filter`), fail2ban (`inet f2b-table`), zapret2 (`ip MTProtoL`), `inet mss443`.
- На entry набор `ru_nets` при этом сжимается до 4 частных сетей. До следующего `ru-nets.timer` (раз в 24 часа) весь российский трафик идёт на выход.
- Docker на exit теряет NAT до своего перезапуска.
- **Инструмент:** только свои таблицы (`table inet vpnkit_*`). Файл вида `delete table …; table … {…}` применяется атомарно через `nft -f` без `flush ruleset`. NAT — в своей таблице, а не в общей `ip nat`, которую делит Docker. После применения `ru_nets` заливается из кэша сразу.

**P-02. Живой набор правил расходится с файлом.**
- Правки на лету через `nft add` попадают в файл не всегда: защита от повторной вставки может сравнить не ту строку, и правило в файл не попадёт. После перезагрузки клиенты остаются без интернета.
- **Инструмент:** правило пишется в файл, файл применяется целиком (только своя таблица), затем проверка: число и хеши правил в живой таблице совпадают с файлом.

**P-03. `accept` в одной таблице не отменяет `drop` в другой на том же хуке.**
- Разрешение для forward должно лежать в той же цепочке, где policy drop (`inet fw forward`). На этом SOCKS5 трижды отваливался за сутки.
- **Инструмент:** одна своя forward-цепочка с policy drop, в неё модули добавляют свои правила через именованные вставки.

**P-04. Docker и policy drop в forward.**
- Правила Docker в `ip filter FORWARD` не помогают, если в `inet fw forward` стоит drop. Нужны явные `iifname "docker0"/"br-*" accept`.
- **Инструмент:** если найден Docker, добавляет эти правила и пишет об этом.

**P-05. Службы, привязанные к адресу туннеля, стартуют раньше туннеля.**
- nginx падал на `bind()` к адресу туннеля — лечилось `net.ipv4.ip_nonlocal_bind=1`.
- **Инструмент:** `ip_nonlocal_bind=1` на entry, плюс drop-in `After=`/`BindsTo=awg-quick@awg0` у служб, которые слушают туннельные адреса.

**P-06. MTU и PMTUD во вложенных туннелях.**
- У awg2 MTU 1260 (есть padding). Клиент с MTU 1280 объявляет MSS 1240, сервер шлёт 1280 байт, и пакет не пролезает.
- ICMP «нужна фрагментация» уходит с адресом туннеля через eth0 и теряется. Короткие ответы проходят, закачки встают.
- **Инструмент:** для каждого клиентского интерфейса в начале forward (до `ct state established`) стоит `tcp option maxseg size set <MTU−40>`.

**P-07. MSS на 443 после переноса 443 на nginx.**
- telemt ограничивал MSS до 1200 (`client_mss`) на своём публичном сокете. Когда 443 перешёл на nginx, ограничение осталось только на loopback, и у части клиентов MTProto завис на «connecting».
- **Инструмент:** отдельная таблица `inet mss443` (SYN и SYN-ACK на eth0:443 → 1200) с приоритетом `mangle - 10`, раньше zapret2.

**P-08. Приоритеты `ip rule` пересекаются.**
- Сторонняя служба может занять те же приоритеты, что у входа AWG (208/212).
- **Инструмент:** реестр приоритетов и fwmark в манифестах. Два модуля с одним приоритетом не встанут.

**P-09. Проверки с самого сервера врут.**
- Трафик на собственный публичный адрес идёт через `lo` и не попадает под правила `iifname eth0` (DNAT SOCKS, zapret2).
- **Инструмент:** проверки входов гоняются **с другого узла**: exit проверяет entry и наоборот. Мобильный ТСПУ проверить может только человек с телефоном, и инструмент так и говорит.

## Версии и совместимость

**P-10. Xray новее 26.3.27 ломает Reality для sing-box-клиентов.**
- С 26.7.28 сервер по умолчанию требует клиента Xray-core ≥ v26.3.27. sing-box 1.13 получает `reality verification failed`, и это неотличимо от блокировки.
- В GitHub меткой latest помечена 26.3.27, а 26.7.28 лежит выше.
- **Инструмент:** версия зафиксирована (`xray.pin`). При обновлении — либо `minClientVer` в `realitySettings`, либо проверка на контрольном sing-box-клиенте.

**P-11. Ванильный sing-box не умеет XHTTP. VLESS Encryption нужен extended ≥ 2.0.**
- Клиент на ванильном sing-box (часто — роутеры) не поднимет записи подписки VLESS-XHTTP; работает только hysteria2.
- Для XHTTP и VLESS Encryption нужен sing-box-extended ≥ 2.0 (для малых роутеров есть extended lite, ~10–15 МБ).

**P-12. AmneziaWG собран из исходников, а PPA устарел.**
- Модуль и tools берутся из git по пину, через DKMS. В DKMS модуль записан как `amneziawg/1.0.0`.
- PPA `amnezia/ppa` отдаёт tools 1.0.20210914 без параметров 3.1: конфиг с `HeaderProtectionKey` не поднимется.
- **Инструмент:** собирает из git по пину и проверяет `modinfo amneziawg | grep version`, а не имя в DKMS.

**P-30. `awg set <if> listen-port` на живом интерфейсе роняет ядро** (Oops в модуле amneziawg).
- **Инструмент:** никогда так не делает. Порт меняется только переподнятием интерфейса (`systemctl restart awg-quick@<if>`).

**P-13. Параметры AWG 3.1 и модуль старше 06.09.2026.**
- `RandomTrailers` исправлен только в модуле от 06.09. Если модуль старше, трейлеры выключены.
- **Инструмент:** проверяет версию модуля по матрице возможностей ([70-updates](70-updates.md)).

## Сервисы entry

**P-15. dnsmasq по SIGHUP не перечитывает конфиг** — только hosts и кэш.
- `systemctl reload` выглядит успешным, но новые `server=`/`address=` не действуют.
- **Инструмент:** после правки `dnsmasq --test`, затем restart и проверка ответа на запрос.

**P-16. Правило `PRIVATE → block` в xray блокирует и собственный DNS xray на 127.0.0.1:53.**
- xray молча уходит к запасным резолверам, и подмена AI-доменов не работает.
- **Инструмент:** шаблон содержит узкое исключение `127.0.0.1/32:53 → direct` **перед** `PRIVATE → block`.

**P-17. Правило `PRIVATE → direct` в xray открывает клиентам внутренние службы узла** (панель на 127.0.0.1:8080, socks 10801).
- **Инструмент:** только `block`, а в `doctor` есть проверка: запрос клиента подписки к 127.0.0.1:8080 не должен получить ответа.

**P-18. Sniffing нужен ради AI-доменов, но без исключений ломает YouTube.**
- Клиенты (INCY) шлют готовый IP, и без sniffing подмена DNS не работает.
- Sniffing включён с исключениями `googlevideo.com` и `gvt1.com`: в ссылки на видео зашит адрес узла, и свой резолв даёт 403.

**P-19. Генераторы перезаписывают конфиги ночью** (`vpnkit-gen.timer`).
- Ручная правка `config.json` xray проживёт до ночи.
- **Инструмент:** правит только генераторы и шаблоны, конфиги не трогает.

**P-20. Сертификат `es` использует sing-box (hysteria2), а deploy-hook certbot перезагружает только nginx.**
- **Инструмент:** hook перезапускает все потребители сертификата из манифестов.

**P-21. MTProxyL: штатное включение WEB с фронтом nginx гасит системный nginx.**
- Он занимает :80 default_server и :443 и не возвращает системный nginx обратно.
- **Инструмент:** только `WEB_FRONTEND=haproxy`, роль фронта берёт системный nginx stream (ssl_preread). Переключать фронт в панели или боте MTProxyL нельзя — инструмент это проверяет в `doctor`.

**P-22. telemt открывает порты не сразу.**
- Порты появляются примерно через 6 секунд после «Прокси запущен» (ждёт STUN).
- **Инструмент:** установка ждёт порт до минуты.

**P-23. zapret2 (MTProto) забирает в NFQUEUE весь TCP 443 и десинхронизирует весь поток.**
- Честный TLS на 443 рядом с ним на мобильных сетях не живёт — отсюда XHTTP на 4443.
- Добавлять в zapret2 `--hostlist-exclude-domains` нельзя: ломает MTProto.

**P-24. Обновление `ru_nets` (`vpnkit-ru-nets.sh`) не трогает набор, если источник вернул меньше 5000 строк.**
- Это правильно. Но после `flush ruleset` набор не восстанавливается до срабатывания таймера (P-01) — поэтому установщик заливает его из кэша сразу.

**P-25. Сети, добавленные пользователем, живут только в памяти.**
- Их стирает следующее обновление списка или перезагрузка.
- **Инструмент:** пользовательские сети хранит в файле, который обновление добавляет к списку.


**P-27. Нет ротации логов.**
- Логи xray растут, geo-файлы xray никто не обновляет.
- **Инструмент:** logrotate для всех своих логов и обновление geo-файлов вместе с xray.

## Общие

**P-50. Секреты в командной строке, коде и журналах.**
- Ключ в аргументах виден в `ps`, пароль записан в коде, токены подписок печатаются в журнал.
- **Инструмент:** секреты только в файлах 600 (EnvironmentFile или LoadCredential), в выводе маскируются.

**P-51. Проверка домена-прикрытия формальными признаками недостаточна** (для Reality).
- `microsoft.com` и `bosch.com` проходят TLS 1.3 + h2, но не работают (bosch согласует P-256).
- ClientHello должен влезать в один сегмент мобильной сети: у `fp=ios` 517 байт, у `chrome` 1754.
- **Инструмент:** кандидата проверяет живым подключением. Отпечаток по умолчанию — `ios`.

**P-52. Reality и голый TCP с Vision на мобильном ТСПУ мертвы** (проверено на тестовых серверах).
- Выживает то, что похоже на настоящий HTTP: XHTTP за TLS, VLESS Encryption поверх XHTTP, hysteria2.
- **Инструмент:** по умолчанию не предлагает Reality как клиентский вход.

**P-53. Сторонние установщики с неприемлемыми побочными эффектами.**
- Бывают установщики, которые делают MASQUERADE клиентов прямо в eth0 мимо каскада, открывают 80 под certbot standalone, выставляют панель наружу и убивают процессы, занявшие порт, или при каждом запуске исполняют скрипт с GitHub.
- **Инструмент:** такие компоненты ставит сам по своему манифесту и берёт у них только бинарник с проверкой sha256. Исключение — MTProxyL: его установщик запускается по закреплённому тегу с явными параметрами, которые не трогают nginx (P-21).

**P-54. Сторонние службы на узле** (Docker, `br-*`, занятый диск).
- **Инструмент:** находит чужие контейнеры и сети, не трогает их и учитывает их ресурсы в `check`.


## Пойманные при обкатке установщика

**P-46. Вложенный heredoc с той же меткой.** Обёртка шага и вложенный файл отката закрывались одной меткой — внешний heredoc обрывался на внутренней, файл отката писался неполным. **Решение:** разные метки (`stepTag`/`rollbackTag`), проверка, что метка не встречается в тексте.

**P-47. `cmd | grep -q` под `set -o pipefail`.** `grep -q` выходит на первом совпадении, `cmd` получает SIGPIPE, конвейер «проваливается» при верном результате. В проверке модуля это давало ложный откат. **Решение:** вывод сначала в переменную, потом `grep <<<"$var"`.
- Ловушка может срабатывать и в скриптах мониторинга, где она даёт ложные оповещения. Массовое `update` может упасть на xray: `ip rule | grep -q` не увидит правило, которое было на месте.
- Теперь `agent/embed_test.go` (pre-commit) запрещает `| grep -q` в скриптах агента.

**P-48. Хостер уже положил свой `/swapfile` (512 МБ).** Проверка «есть ли `/swapfile`» пропускала добавление swap, хотя его мало. **Решение:** считать суммарный swap; при нехватке добавлять `/swapfile.vpnkit`, хостерский не трогать.

**P-49. Go-клиент SSH и смена типа ключа хоста.** После обновления OpenSSH сервер стал первым предлагать ECDSA, а закреплён был RSA: клиент проверяет только согласованный тип и видит «ключ изменился», хотя прежний ключ на месте (сверено `ssh-keyscan`). **Решение:** просить у узла ровно закреплённые типы (`HostKeyAlgorithms` из known_hosts), для новых узлов — Ed25519 первым.

**P-55. Образ хостера с двумя настройками сети.** ifupdown и cloud-init/netplan оба поднимают `eth0`; после перезагрузки `networking.service` и `ifup@eth0` падают с «Address already assigned», сеть при этом работает. **Инструмент:** `check` фиксирует упавшие службы ДО установки, чтобы отличать чужие от своих.

**P-56. `http2 on;` есть только с nginx 1.25.1.** В Ubuntu 24.04 стоит nginx 1.24, и конфиг с этой директивой не проходит `nginx -t`. В 26.04 (1.28) она работает, а старый флаг `listen … http2` там устарел. **Инструмент:** nginx-tls выбирает форму по версии nginx. Поймано на тестовых серверах: установка упала на `nginx -t` и откатилась.

**P-57. Доступность входа из РФ проверяется только из РФ и без VPN.** Сервер может быть заблокирован целиком по IP: не отвечают ни ping, ни 22, ни 80. Снаружи (с выхода, из Европы) всё при этом работает. На тестовых серверах вход мог быть недоступен из РФ, а снаружи отвечать. Проба с ПК, на котором включён VPN, идёт мимо блокировки и врёт. **Инструмент:** мастер проверяет вход с ПК пользователя (он в РФ), просит выключить VPN на время пробы и сверяет с контрольным адресом. Если вход недоступен, каскад бессмыслен, и ставить на этот сервер нельзя. Тестовые серверы с такими адресами годятся только для проверки модулей.

**P-58. Правка скриптов программой, которая сама разбирает escape-последовательности.** Python-вставки трижды превратили `\1` в управляющий символ и `
` в настоящий перевод строки. Шаг падал уже на узле или ломал сборку. **Инструмент:** тест `agent/embed_test.go` (управляющие символы, CRLF, `bash -n`, синтаксис Python) стоит в pre-commit.

**P-59. Права файлов через umask.** Генератор создавал файлы подписок с режимом 0644 через `os.open`, а режим проходит через umask. Восстановление запускает его под `umask 077`, файл получался 0600, и nginx отвечал 403. **Инструмент:** права ставятся явно через `chmod`, а восстановление в конце проверяет каждую подписку через 443.

**P-62. Новое ядро без модуля AmneziaWG.** unattended-upgrades поставил Ubuntu 7.0.0-38, а модуль AmneziaWG 3.1.20260812 под него не собрался: Ubuntu перенесла из 7.1.5 новую сигнатуру `setup_udp_tunnel_sock(net, struct sock *, cfg)`, а `compat.h` модуля судит по номеру ядра (`< 7.1.5`) и подставляет старую. DKMS упал, пакеты ядра остались `iF/iU` без initrd, но -38 уже стоял первым в GRUB: любая перезагрузка — узел без AWG (или не загрузился бы вовсе), каскад лежит. unattended-upgrades продолжал падать, обновления безопасности копились. `udp_tunnel_sock_release` в -38 НЕ менялась. **Инструмент:** модуль `amneziawg` берёт тег v3.1.20260906 и накладывает `files/ubuntu-udp-tunnel-sk.patch` (Kbuild ищет новую сигнатуру в заголовках и ставит `-DAWG_UDP_TUNNEL_SETUP_SK`; не ложится — сборка как есть), прописывает версию тега в `version.h` (в 0906 там осталось 0812) и собирает модуль под все поставленные ядра с заголовками. Мониторинг: `kernel_awg` (в ядре, куда узел загрузится следующим, нет модуля) и `dpkg` (недоустановленные пакеты). Перезагрузку в новое ядро делать через однократный `grub-reboot` и самопроверку с откатом (см. 70-updates).
