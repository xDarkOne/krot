# Как устроен vpnkit

Документ для тех, кто правит код или добавляет модуль. Как пользоваться — [USAGE.md](USAGE.md).

## Принципы

- **Пульт решает, узел исполняет.** Выбор версий, генерация ключей и параметров, порядок установки, проверка совместимости — на компьютере пользователя («пульт»). На сервер уходят готовые параметры и короткие идемпотентные скрипты агентов.
- **Каждый шаг можно откатить.** Перед изменениями снимается снимок и взводится «мёртвая рука». Если проверка не прошла или пульт пропал, узел откатится сам.
- **Повторный запуск безопасен.** Модуль, поставленный дважды, не меняет ничего лишнего и перезапускает службы, только если их конфиг или бинарник действительно изменились.
- **Секреты только у пользователя.** Они лежат в `secrets.age`, зашифрованном его ключом (`~/.vpnkit/age.key`). На узлах — только файлы с правами 600, никогда в аргументах команд и журналах.
- **Ядро — библиотека, окно — тонкое.** Вся логика в `internal/`, её одинаково используют CLI (`cmd/vpnkit`) и окно Wails (`app/`). Окно только показывает данные и спрашивает пользователя. Платформенные мелочи (открыть папку, пути) спрятаны за `runtime.GOOS`. Так ядро можно будет переиспользовать и в мобильном приложении (gomobile): у Wails нет Android.

## Схемы и роли

| Схема (`topology`) | Узлы (`role`) | Трафик клиента |
|---|---|---|
| `cascade` | `entry` (Россия), `exit` (за границей) | устройство → вход; российское идёт напрямую с входа, остальное через туннель `awg0` и выходит с выхода |
| `solo` | `solo` (за границей) | устройство → сервер → интернет |

## Код

```
cmd/vpnkit/        CLI: разбор команд, вывод в терминал
app/               окно (Wails v2): Go-обвязка app/*.go, интерфейс app/frontend (vanilla JS + Vite)
modules/           манифесты модулей (*.yaml, встраиваются в бинарник) + каталог (catalog.go)
agent/             скрипты для узлов (встраиваются): lib.sh — общая библиотека,
                   <модуль>/{preflight,install,verify,rollback}.sh, <модуль>/files/ — файлы на узел,
                   common/files/vpnkit-gen.py — генератор конфигов xray, sing-box, подписок и nginx stream
internal/
  inventory        inventory.yaml: узлы, роли, схема, параметры модулей
  secrets          хранилище secrets.age (age): ключи, пароли, токены
  remote           SSH: ключ или пароль, свой known_hosts (~/.vpnkit/known_hosts), прыжок через узел
  bootstrap        первый вход: пароль root → ключ пульта, пароль отключается
  probe            факты об узле и вердикт «подходит ли под роль»

  modexec          установка модуля: параметры (prepare.go), снимок, мёртвая рука, шаги, метка
  wizard           каталог → выбор → план → прогон по шагам; обновления
  clients          клиенты AmneziaWG, подписки и Telegram-прокси: профили, ссылки, QR
  health, status   проверки здоровья из манифестов; сводка по узлу
  backup           забрать, проверить, распаковать резервную копию
  alerts           бот Telegram для оповещений
  profile          сверка версий: пины пульта, узлы, свежие релизы
  awgkeys          ключи и обфускация AmneziaWG 3.1
  selfupdate       обновление самого vpnkit из релизов GitHub (сверка по SHA256SUMS, подмена файла)
```

## Модуль

Модуль — это манифест `modules/<имя>.yaml` и каталог `agent/<имя>/`.

**Манифест** (схема — [modules/_schema.yaml](../modules/_schema.yaml)) описывает:
- роли, зависимости (`requires`, `requires_if` по роли или схеме);
- порты, файлы, юниты, проверки здоровья (`health`);
- ловушки (`pitfalls` → [60-pitfalls.md](60-pitfalls.md));
- срок мёртвой руки (`deadman_sec`);
- **блок `catalog`** — как модуль предлагается пользователю:

```yaml
catalog:
  group: access            # base | cascade | access | extra — раздел в мастере
  order: 70                # порядок установки: всё, что нужно модулю, — раньше
  default: true            # включён, пока пользователь не выключил (required — нельзя выключить;
                           # auto — не выбирается, ставится, когда нужен другим)
  domain: true             # нужны имена nginx-tls; без домена не ставится
  place: {cascade: [entry], solo: [solo]}   # куда ставится в каждой схеме
  title: VLESS (XHTTP, постквантовый)
  what: Входы подписки поверх обычного HTTPS
  why: Трафик неотличим от посещения сайта…
  cost: ≈60 МБ памяти
```

Модуль без блока `catalog` установщик не предлагает.

**Скрипты агента** (bash, `set -euo pipefail`, перед шагом подключается `agent/lib.sh`):
- `preflight.sh` — проверки до любых изменений: места, портов, зависимостей;
- `install.sh` — установка. Файлы пишутся через `put` (атомарно, со снимком), пакеты — через `apt_install`. Всё созданное записывается в `$VK_RUN/created.list`, чтобы откат знал, что убрать;
- `verify.sh` — проверка, что модуль действительно работает;
- `rollback.sh` — вернуть снимок и снять созданное этим прогоном.

Параметры приходят переменными `VK_*`. Их собирает `internal/modexec/prepare.go` из inventory и хранилища. Секреты, которых ещё нет, генерируются и сохраняются **до** установки, поэтому повтор даёт те же значения.

`go test ./agent/` проверяет скрипты: `bash -n`, запрет `| grep -q` под pipefail (P-47), управляющие символы. `go test ./internal/wizard/` сверяет каталог: у модуля есть скрипты, группа и пояснения, а всё, что ему нужно, ставится на тот же узел раньше него.

## Установка модуля (`modexec.Install`)

1. Пульт готовит параметры и проверяет `preflight`. Если проверка не прошла, ничего не менялось.
2. На узле пишется `rollback.sh` и взводится таймер мёртвой руки (`systemd-run --on-active`).
3. Выкладываются файлы модуля, выполняются `install` и `verify`.
4. Успех: таймер снимается, на узле пишется метка `/var/lib/vpnkit/modules/<модуль>` с отпечатком кода (`code=`).
5. Ошибка: откат сразу. Если пульт пропал, откат по таймеру.

**Отпечаток кода** — sha256 от скриптов модуля, общей библиотеки, манифеста и пинов версий. `vpnkit update` и полоса «Доступны обновления» в окне сравнивают отпечатки на узлах с пультом и переставляют отставшие модули.

## План (`internal/wizard`)

- `Select(topo, node)`:
  - модуль включён, если он обязателен, выбран пользователем (`modules.<имя>.enabled: true`) или включён по умолчанию и не выключен;
  - к включённым добавляется всё, что им нужно на этом узле;
  - модуль, которому не хватает домена или нужного модуля, выключенного пользователем, не ставится — с причиной.
- `Plan` — шаги в порядке каталога; на каждом модуле выход раньше входа.
- `Problems` — чего не хватает: например, ни одного способа подключения.
- `Run` — шаги по одному; на первой ошибке остановка, повтор продолжит с упавшего.

## Версии сторонних компонентов

Бинарники и исходники берутся только по закреплённой версии со сверкой sha256: xray, sing-box, telemt, теги AmneziaWG и MTProxyL. Пины лежат в `internal/modexec/prepare.go`. Смена пина меняет отпечаток модуля, и обновление дойдёт до пользователей. Как поднимать версии — [70-updates.md](70-updates.md).

## Релизы

Тег `vX.Y.Z` запускает [.github/workflows/release.yml](../.github/workflows/release.yml):
- CLI под шесть платформ (без cgo);
- окно:
  - Linux amd64 и arm64 (Ubuntu 22.04, glibc 2.35);
  - Windows amd64 и arm64 (кросс-сборка Wails);
  - macOS universal;
- `SHA256SUMS`, GitHub Release с текстом из `packaging/release-notes.md`.

Пробная сборка без публикации — Actions → release → Run workflow.
